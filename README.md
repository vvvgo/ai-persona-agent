# NetTyan

Прототип ИИ-персонажа для онлайн-трансляций: играет в Minecraft, читает чат
и отвечает голосом. Обёртка над языковой моделью плюс инструменты вокруг неё —
распознавание речи, синтез речи, сбор сообщений с площадок, модерация текста,
аватар.

Проект исследовательский. Это не готовый продукт и не «платформа»: набор частей,
которые собираются в работающего персонажа, если потратить вечер на настройку.

## Эта версия: персонаж Rancher

Форк NetTyan с интенсива AI Persona Lab. Персонаж — Rancher, фермер-обжора:
думает только об огороде и запасах на зиму, шутит про урожай и «собирает урожай
с чужих грядок» (в чате, не в игре). Играет на публичном сервере mc.agicraft.ru.

Что изменено по сравнению с оригиналом:

- `resources/Characters/Rancher/` — характер, идеи для разговора, прозвища для игроков.
- Языковая модель — GLM-5.3-Flash от Z.ai через LiteLLM (`zai/glm-5.3-flash`).
  Через `CORE_LLM_EXTRA_BODY` передаются параметры провайдера, например
  низкий уровень «размышлений» у GLM.
- Чат-агент настраивается в `.env`:
  `CHAT_AGENT_MAX_RESPONSE_TOKENS` — размышления GLM съедали лимит в 500 токенов;
  `CHAT_AGENT_DISABLE_INTERRUPTS` — на сервере, где болтают другие боты,
  прерывания не давали ответу дойти до конца;
  `CHAT_AGENT_VOICE_CHAT_FALLBACK` — GLM часто отвечает только инструментами,
  тогда вслух произносится его сообщение из чата.
- Публичный сервер: `MC_CHAT_PREFIX` отправляет сообщения в глобальный чат,
  `MC_BLACKLIST_ACTIONS` запрещает действия, которые ломают блоки. Описание
  mc.agicraft.ru добавлено в `minecraft_server_bank.yml`, команда `@get` —
  в список действий.
- Из сообщений в игровой чат вырезаются метки эмоций вроде `*happy*`.
- Пароль Postgres в `docker-compose.yml` берётся из `.env`.
- `start_rancher.ps1` запускает всё одним скриптом на Windows: контейнеры
  (Docker в WSL), VTube Studio, OBS, простой TTS и самого агента.
  `run_rancher.ps1` пишет лог агента в `data/logs/`.

Ключи и пароли лежат только в `.env` и `.env.postgres`, оба файла в `.gitignore`.
Шаблон настроек — `.env.example`.

## Что внутри

| Часть | Где | Что делает |
|---|---|---|
| Агент | `src/agent/` | логика поведения поверх языковой модели, реакции, промпты |
| Персонаж | `src/character/` | характер, эмоции, подбор голосовых реплик |
| Синтез речи | `src/tts/`, `docker/tts/` | Fish TTS в контейнере либо простой сервер на vosk |
| Распознавание речи | `docker/stt/` | sherpa-onnx, определение речи (VAD), потоковая расшифровка |
| Сбор сообщений | `src/data_collectors/` | YouTube, Twitch, Trovo, донаты |
| Модерация | `docker/filter/` | фильтрация текста, транслитерация, словари |
| Хранилище | `src/data_flow/` | модели, слой доступа к данным, миграции |
| Аватар | `src/live2d/`, `src/front/` | Live2D и вывод на трансляцию |
| Игра | внешний мод [UnionClef](https://github.com/3ndetz/unionclef) | управление персонажем в Minecraft |

## Быстрый старт

```bash
nettyan -rof
```

Это для случая, когда всё уже настроено. С нуля — по документации ниже,
там по шагам: окружение, конфигурация, запуск.

Минимум, который нужен до первого запуска: ffmpeg, Python-окружение,
заполненный `.env`. Для синтеза речи и фильтрации — Docker. Под Windows
запускать напрямую, не через WSL: со звуковыми устройствами в WSL начинаются
танцы с бубном.

## Что входит в поставку

Проект запускается из коробки: голосовые образцы персонажа и звуковые сигналы
интерфейса лежат в репозитории. Всё это сделано самим проектом — сигналы
синтезированы скриптом `tools/make_fx_sounds.py`, реплики диктора и образцы
голоса получены синтезом речи. Чужих сэмплов в репозитории нет.

Образцы голоса стандартные и одинаковые для всех, кто склонировал репозиторий, —
свой персонаж начинается с их замены, см. [Свои звуки и голос](docs/help/instructions/SOUNDS.md).

Реальных данных пользователей в репозитории нет: пример контекста чата в
`data/debug/ctx_chat.json` выдуман целиком, а база модерации не входит в
поставку и создаётся на вашей стороне.
